# 01. Linux の基本

Kubernetes / OpenShift は Linux 上でコンテナを動かす前提です。  
ここでは **パス操作 + ファイル確認 + プロセス + 疎通** を、各コマンドの意味と目的付きで身につけます。

コンテナは「隔離された Linux プロセス」に近いので、ここで覚える操作はあとで `kubectl exec` や障害切り分けでも同じ型で使います。

## 前提

- macOS ターミナル、または WSL / Linux（すべて無料）
- 追加クラウド不要

---

## コマンド詳解（意味と目的）

### いまどこにいるか・何があるか

#### `pwd`（Print Working Directory）

| | |
|--|--|
| **意味** | 今いるディレクトリの絶対パスを表示する |
| **目的** | 「自分はどの場所で作業しているか」を確定する |
| **K8s/運用での使い所** | マニフェストを `apply` する前に、正しいディレクトリか確認する。コンテナに入った直後もまず `pwd` |

```bash
pwd
```

#### `cd`（Change Directory）

| | |
|--|--|
| **意味** | 作業ディレクトリを移動する |
| **目的** | 目的のフォルダへ移動してからコマンドを打つ |
| **よく使う形** | `cd /path/to/dir` / `cd ..`（一つ上） / `cd ~`（ホーム） / `cd -`（直前の場所） |

```bash
cd /tmp
pwd
cd -
```

#### `ls`（List）

| | |
|--|--|
| **意味** | ディレクトリ内のファイル・フォルダを一覧する |
| **目的** | 「何があるか」「権限・所有者はどうか」を把握する |
| **重要オプション** | `-l` 詳細（権限・サイズ・日時）、`-a` 隠しファイル（`.` 始まり）も含む → よく `ls -la` |

```bash
ls -la
```

`ls -la` の見方（左からざっくり）:

```text
-rw-r--r--  1 user  staff  123  Jul 12 01:00 file.txt
│           │  │     │      │
│           │  │     │      └ サイズ
│           │  │     └ グループ
│           │  └ 所有者
│           └ リンク数など
└ 権限（誰が読める/書ける/実行できるか）
```

権限はあとで `chmod` / コンテナのファイル権限トラブルで効いてきます。

### ファイルを作る・見る・探す

#### `echo`

| | |
|--|--|
| **意味** | 文字列を標準出力に出す |
| **目的** | メッセージ表示、またはリダイレクトで簡単なファイル作成 |
| **`>` との組み合わせ** | `echo "text" > file` は「file に text を書き込む」（既存は上書き） |

```bash
echo "hello k8s" > /tmp/k8s-learn.txt
```

`>>` は追記。`>` は上書き。ログや設定の扱いで取り違えると事故るので意識する。

#### `cat`（Concatenate）

| | |
|--|--|
| **意味** | ファイルの中身をまとめて表示する |
| **目的** | 短い設定ファイル・ログの全体確認 |
| **注意** | 巨大ログには不向き（画面が流れる）。長いものは `less` |

```bash
cat /tmp/k8s-learn.txt
```

#### `less`

| | |
|--|--|
| **意味** | ファイルをページ単位で見る（スクロール可能） |
| **目的** | 長いログ・設定を安全に読む |
| **操作** | スペースで次へ、`b` で戻る、`/単語` で検索、`q` で終了 |

```bash
# 例: less /var/log/system.log   # 環境によってパスは異なる
```

#### `grep`

| | |
|--|--|
| **意味** | テキストから条件に合う行を抜き出す |
| **目的** | ログや設定から「知りたい文字列だけ」見つける |
| **K8s/運用での使い所** | `kubectl logs ... \| grep Error`、設定ファイル内のキー検索 |
| **よく使う形** | `grep パターン ファイル` / `コマンド \| grep パターン` / `-i`（大小無視） / `-n`（行番号） |

```bash
grep k8s /tmp/k8s-learn.txt
grep -n k8s /tmp/k8s-learn.txt
```

### プロセスと「誰として動いているか」

#### `ps`（Process Status）

| | |
|--|--|
| **意味** | 動いているプロセス（実行中プログラム）の一覧 |
| **目的** | 「何が動いているか」「誰のプロセスか」「PID は何か」を見る |
| **`ps aux`** | 他ユーザー含め、詳細付きで広く一覧（環境によって表示形式に差あり） |
| **K8sとの接点** | コンテナの中も結局プロセス。Pod 内で `ps` するとアプリプロセスが見える |

```bash
ps aux | head
```

`|`（パイプ）は「左の出力を右の入力に渡す」。`head` は先頭数行だけ表示（多すぎる出力を抑える）。

#### `top` / （macOS なら）同様の監視

| | |
|--|--|
| **意味** | CPU・メモリ使用をリアルタイム表示 |
| **目的** | 重いプロセス、リソース逼迫の一次確認 |
| **操作** | `q` で終了。詳細は環境の man を参照 |

```bash
# top
# 終わったら q
```

ノードやコンテナの「重い」切り分けの原型です（K8s では `kubectl top` もある）。

#### `whoami`

| | |
|--|--|
| **意味** | 今のユーザー名を表示 |
| **目的** | 「今どのユーザーで操作しているか」を確認 |
| **運用での使い所** | root でやっていないか、アプリ用ユーザーか、を確認。権限トラブルの入口 |

```bash
whoami
```

#### `id`

| | |
|--|--|
| **意味** | ユーザー ID（UID）・グループ ID（GID）・所属グループを表示 |
| **目的** | 権限の正体を数字で確認する |
| **K8s/OpenShiftでの重要性** | コンテナはしばしば「特定 UID」で動く。OpenShift の SCC でも UID が効く。`id` で「誰として動いているか」が分かる |

```bash
id
```

例: `uid=501(moro) gid=20(staff) ...` → 名前だけでなく番号が本質。

### ネットワーク疎通（運用の基本技）

#### `curl`

| | |
|--|--|
| **意味** | HTTP/HTTPS などでリクエストを送るクライアント |
| **目的** | 「その URL に届くか」「ステータスは何か」を確認 |
| **`-I`** | ヘッダのみ取得（GET のボディを省略。生死確認に便利） |
| **K8s/運用での使い所** | Service / Route / Ingress の疎通、アプリヘルスチェックの手確認 |

```bash
curl -I https://example.com
```

成功の目安: `HTTP/2 200` や `HTTP/1.1 200` など。  
失敗したら「DNSか」「接続か」「TLSか」「アプリか」を切り分ける入口になる。

#### `dig` / `nslookup`

| | |
|--|--|
| **意味** | 名前（ドメイン）を IP に解決する問い合わせ |
| **目的** | 「名前解決できているか」を切り分ける |
| **運用での使い所** | Route / Ingress / 外部 API で「名前が取れない」疑いの確認 |

```bash
# 入っていればどれか
# dig example.com +short
# nslookup example.com
```

| 部分 | 意味 | 目的 |
|------|------|------|
| `dig example.com` | example.com の DNS 問い合わせ | 名前が IP に解決できるか確認（返る IP は example.com 側のアドレス。自分の PC ではない） |
| `+short` | 詳細を省略して結果だけ表示 | 長い DNS 応答ではなく IP 等だけ見たいとき |

`curl` 失敗時に、まず名前解決か通信かを分けるのが定石です。

#### `ss` / `lsof`（ポート確認）

| | |
|--|--|
| **意味** | どのプロセスがどのポートを待ち受けているか見る |
| **目的** | 「80/8080 は誰が listen しているか」「ポート衝突か」を確認 |
| **環境差** | Linux は `ss` が主流。macOS は `lsof` が使いやすいことが多い |

```bash
# macOS 例
# lsof -nP -iTCP -sTCP:LISTEN | head

# Linux 例
# ss -lntp | head
```

Service の `targetPort` とコンテナの listen ポートがずれている、という障害の原型理解になります。

### 権限（後の Step で再登場）

#### `chmod` / `chown`

| コマンド | 意味 | 目的 |
|----------|------|------|
| `chmod` | ファイルの権限ビットを変える | 実行可にする、書込を閉じる、など |
| `chown` | 所有者・グループを変える | 誰のファイルかを変える（多くの環境で管理者権限が必要） |

今は「そういうものがある」で十分。コンテナのボリューム権限エラーでまた出会います。

## ハンズオン（上から実行）

```bash
# 場所の把握
pwd
ls -la

# 移動の感覚
cd /tmp
pwd
cd -

# ファイル作成・閲覧・検索
echo "hello k8s" > /tmp/k8s-learn.txt
cat /tmp/k8s-learn.txt
grep k8s /tmp/k8s-learn.txt

# プロセスとユーザー
ps aux | head
whoami
id
```

### 疎通

```bash
curl -I https://example.com
```

```bash
# dig example.com +short
# nslookup example.com
```

## 期待結果

| 操作 | 成功の目安 |
|------|------------|
| `pwd` | `/Users/...` や `/home/...` などパスが表示される |
| `cat /tmp/k8s-learn.txt` | `hello k8s` |
| `grep k8s ...` | `hello k8s` の行が出る |
| `whoami` / `id` | 自分のユーザー名と UID が出る |
| `curl -I https://example.com` | `HTTP/2 200` または `HTTP/1.1 200` など |

## トラブル時

| 症状 | 対処 |
|------|------|
| `curl: command not found` | WSL なら `sudo apt update && sudo apt install -y curl` |
| 社内プロキシで curl 失敗 | 別ネットワーク、または後続 Step で再試行 |
| `dig` / `ss` が無い | 必須ではない。`curl` と `ps` ができれば先へ進める |
